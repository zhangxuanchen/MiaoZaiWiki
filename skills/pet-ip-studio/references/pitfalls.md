# 坑清单 · 动手前扫一眼

这些全是真踩过的。**共同点：大多数不报错，只是结果不对** —— 所以值得先看。

---

## A. 验证类（最容易中招）

**A1 · 编译失败却继续跑，用的是旧二进制**
改完源码没重新编译，接着跑的还是上一轮的程序，输出看着挺正常。
- 症状：改完看输出「像没生效」
- 修法：**编译失败必须当场停**。`build.sh` 已做到这一点；手敲命令时自己盯
- 判据：断言条数、输出标记有没有按预期变。数字没变 = 跑的是旧的

**A2 · 断言"过了"，其实什么都没验**
被测函数有缓存，第二次调用直接 return，断言里的清理/还原逻辑根本没执行。
- 症状：两条断言 "PASS" 了两次，但对应用例是空转
- 修法：用**没缓存过**的输入；加新断言时先故意改坏，确认它会红

**A3 · `try?` 吞掉写入失败**
`try? png.write(to: url)` —— 目录不存在/没权限时静默失败，工具照样打印"已导出"。
- 症状：输出说导出了，去读文件发现不存在
- 修法：写文件用 `do/catch`，失败要报错并返回非零

**A4 · 判据本身不可测**
做"嘴微微张开"，第一版用描边色画一条缝 —— 深色叠深色，整图只多 6 个像素。
- 症状：改动是真的，但测不出来（也就无法判断对错）
- 修法：问自己「**如果这是错的，我能测出来吗**」。6px 就是答案
- 那次的解法：改成"透出一点舌头色"，变成 0 → 38 像素，图和断言同时变清楚

**A5 · 写死某个 id / 路径来判断环境**
原本用 `Bundle.main.bundleIdentifier == "local.catpet"` 判断"是不是打包后的 app"。
换了 bundle id 之后判断失效 —— 而失效的症状是"设置改完重启就没了"，很难查。
- 修法：判据取"确实在 bundle 里"，跟 id 叫什么无关

**A6 · 工具放在 `/tmp`**
系统会定期清理 `/tmp`，机器重启也会清。曾经整套验证脚手架（190+ 条断言、
指纹脚本）放那儿，现在找不到了。
- 修法：**跑得通的东西当场落进项目目录**。`/tmp` 只放这一分钟用完就扔的中间文件

## B. shell 类

**B1 · `$VAR` 后面紧跟中文**
`echo "$PY（…）"` —— bash 会把全角括号的首字节当成变量名的一部分，
报 `PY�: unbound variable`，脚本当场挂。
- 修法：写成 `${PY}`
- 扫一遍：`python3 dist/check_shell_cjk.py *.sh`

**B2 · zsh 数组是 1-indexed**（bash 是 0）
```zsh
declare -a A=("a" "b"); echo ${A[0]}   # zsh: 空！bash: "a"
```
- 症状：循环少跑一轮、少生成一个文件，输出看着"正常"
- 修法：跨 shell 的脚本一律 `bash script.sh` 跑

**B3 · zsh 默认不做 word splitting**
```zsh
for s in "16 foo"; do set -- $s; echo $1; done   # zsh: 整串；bash: "16"
```
- 修法：用 `while read -r a b; do ... done <<'EOF'`（两种 shell 都对）

**B4 · `pipefail` 让 `ls | head` 变成致命错误**
脚本开头 `set -euo pipefail`，然后 `-n "$(ls xxx | head -1)"` ——
没匹配时 `ls` 返回非零，管道失败，赋值语句失败，**脚本静默退出**。
- 症状：脚本跑一半没了，一句错误都不打印
- 修法：加 `|| true`，或者干脆别用 glob 猜路径（让程序自己报路径）

**B5 · `[ -n "$x" ] && cmd` 在 `set -e` 下会终止脚本**
条件为假时整行返回非零 —— 于是"没找到"被当成错误。
- 修法：写成 `if [ -n "$x" ]; then cmd; fi`

## C. 绘制 / 排版类

**C1 · 文字高度给不够会静默裁切**
`NSAttributedString.draw(in:)` 的 rect 高度只够一行时，多行文字**只画第一行**，
不报错不警告。
- 修法：按行数算高度 `h = size * 1.40 * 行数`

**C2 · 坐标推算别漏整体缩放**
按 `headC` 推算某部件的位置，推出来 y≈84，实测 54~66 —— 漏了 `draw()` 里
那层 `CAT_SCALE` 整体缩放。
- 修法：**先打印一次实测值，再按实测 ± 余量写阈值**。别用推算的坐标写断言

**C3 · 先写内容，再算画布尺寸**
排版脚本最常见的返工：内容写完了才发现画布不够，文字/图片被裁。
- 修法：先列出所有元素并算出需要的宽高，再定画布。最后一道防线是渲染出来看一眼

**C4 · 离屏渲染会污染全局状态**
渲染时会设 `CatView.renderTime`（不还原 = 桌面上的宠物动画被钉死）
和全局 `LANG`（不还原 = 语言串了）。
- 修法：都用 `defer` 还回去

## D. 项目结构类

**D1 · 枚举新档一律追加在末尾**
下标会落进用户配置。插在中间会让已有用户的设置全部错位。

**D2 · per-pet 字段要同时改 `load()` 和 `save()`**
漏一个就是"存了等于没存"。踩过两次。

**D3 · 单例存储的测试顺序**
配置是单例、有落盘逻辑。测试脚本里"落盘"那一段必须放**最前**，
否则脚本内存里那份旧配置会被整体写回真实配置。
- 兜底：用环境变量把配置路径指到沙箱（这个项目里是 `MIAOZANG_CONFIG`）

**D4 · Swift 嵌套字面量太大 = 类型推断超时**
一个巨大的嵌套字典字面量会报
`unable to type-check this expression in reasonable time`。
- 修法：拆成"先建空字典、再逐项赋值"

**D5 · 别用 `#filePath`**
它会把构建时的绝对路径烤进二进制 —— 项目一挪地方就失效，而且那路径本身
也不该外泄。
- 修法：用可执行文件的位置推项目根

## 一句话总结

上面 20 条里，**只有 B1 和 D1 是"会报错"的**，其余全是静默的。

所以真正的纪律不是"小心一点"，而是：
**每做完一步，都问一句「如果这里错了，我怎么知道？」**
答不上来的地方，就是需要加断言的地方。
